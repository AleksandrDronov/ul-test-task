# Спецификация ИИ-агента

## Проект

Разработать production-ready SPA для работы с грузовыми аукционами
согласно `openapi.auctions.v0.json` и требованиям тестового задания.

## Цель

- Строго соблюдать контракт OpenAPI.
- Писать чистый, масштабируемый и типобезопасный код.
- При конфликте между архитектурными предпочтениями и требованиями
  задания всегда выбирать требования задания.

## Стек технологий

- React
- TypeScript
- Vite
- TanStack Router
- TanStack Query
- React Hook Form
- Zod
- MSW
- Zustand
- Feature-Sliced Design

## Правила

### OpenAPI

- OpenAPI --- единственный источник истины.
- Не придумывать новые поля.
- Строго соблюдать enum, nullable-поля и контракты запросов/ответов.

### Архитектура

Использовать Feature-Sliced Design:

```text
src/
  app/
  pages/
  widgets/
  features/
  entities/
  shared/
```

### Именование компонентов

Все React-компоненты должны иметь суффикс:

```text
.component.tsx
```

### TypeScript

- Не использовать `any`.
- Не использовать `as any`.
- Избегать небезопасных приведения типов.

### DTO

Разделять: - DTO - ViewModel - Mapper

UI не должен работать с DTO напрямую.

### Query Keys

    auctions.list
    auction.detail
    auction.bets

Mutation:

    setBet

После успешной мутации инвалидировать: - list - detail - bets

### MSW

MSW должен хранить состояние приложения.

После создания ставки: - обновить текущую цену; - обновить историю
ставок; - обновить статус пользователя; - обновить список аукционов.

### Формы

Использовать React Hook Form + Zod.

Проверять: - обязательность поля; - цена \> 0; - min; - max; - step.

### Search Params

Хранить фильтры в URL. Валидировать через Zod.

### Состояния интерфейса

Каждый запрос должен поддерживать: - Loading - Skeleton - Empty -
Error - Success

### Ошибки

Обрабатывать: - 401 - 404 - 422 - 503

### Производительность

- Избегать лишних перерисовок.
- Не допускать дублирования запросов.
- Делать компоненты небольшими.

### Тестирование

Минимальный набор тестов: - парсер search params; - request builder; -
mapper; - валидация Zod.

### README

Описать: - установку; - запуск; - архитектуру; - структуру проекта; -
тестирование; - известные ограничения.
